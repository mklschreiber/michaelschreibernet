## Story

As a visitor of michaelschreiber.net, I want the projects page to list the
"myStandby - LandingPage" project with a short description, links and
screenshots, so that I get all information about all of Michael's
repositories.

Jira: MS-1 — https://mklschreiber.atlassian.net/browse/MS-1

Acceptance criteria (from Jira):

- AC-1: Project "myStandby - LandingPage" is listed on the project page.
- AC-2: The project has a short description generated by AI.
- AC-3: The link https://www.mystandby.app is referenced.
- AC-4: The GitHub repository https://github.com/mklschreiber/myStandby-LandingPage
  is referenced.
- AC-5: Pictures are scaled for the different aspect ratios (performance
  optimization).

## Current State

- `app/src/data/projects.json` holds the project entries. `ProjectOverviewPage.vue`
  renders them in array order in a single-column grid (`minmax(0, 1fr)`), one
  `ProjectCard.vue` per entry, keyed by `id`.
- `app/src/types/project.ts` defines `Project` with **one** optional link
  (`link` + `linkTextKey`) and optional `images: ProjectImage[]`
  (`base` path without size suffix, plus `altKey`).
- `ProjectCard.vue` builds `srcset` from `IMAGE_WIDTHS = [320, 640, 960, 1280,
  1600, 1920]` as `${base}-${width}.jpg`, uses `${base}-960.jpg` as `src`, and
  `${base}-1920.jpg` in the lightbox. The image box is `aspect-ratio: 3 / 2`
  with `object-fit: cover`.
- Text lives in flat keys under `projects.*` in `app/src/i18n/locales/de.ts`
  and `en.ts`, typed by `MessageSchema` in `app/src/i18n/types.ts`.
- Existing variants in `app/public/` (from commit `12e8f44`) sit next to the
  unsuffixed original, for example `page_macbook.jpg` plus `page_macbook-320.jpg`
  to `page_macbook-1920.jpg`. Re-encoding `page_macbook.jpg` with macOS
  `sips -s format jpeg -s formatOptions 80` at 1920px gives a file that is
  byte-identical to the committed `page_macbook-1920.jpg`. So the convention is
  `sips`, JPEG quality 80, widths 320 to 1920, aspect ratio kept.

## Architecture Decisions

### D1 — Replace the single link with a `links` list (AC-3, AC-4)

The new project needs two links (website and repository). `Project` allows only
one. Options:

1. Add a second optional field such as `repositoryLink`. This creates two
   parallel link shapes and special-case template code.
2. **Replace `link`/`linkTextKey` with `links?: ProjectLink[]`**, where
   `ProjectLink = { url: string; textKey: string }`.

**Decision: option 2.** A list is the natural model for "a project has some
links". The card renders it with one `v-for`. Only two existing entries and one
test mock use the old fields, so the migration is small. No compatibility layer
for the old fields is kept: `projects.json` is the only data source, and
keeping both shapes would only add dead code.

Existing entries are migrated 1:1 (same URL, same text key, now inside
`links`). The visible output for them stays the same.

Order inside `links`: the primary destination (website) first, the repository
second.

### D2 — Placement: directly after the myStandby app entry

The new entry is inserted as the **second** element of the array, between
myStandby (id 1) and michaelschreiber.net (id 2). It belongs with the myStandby
app, so visitors see the app and its landing page together.

It gets **`id: 3`**. Ids are only stable keys (`:key`), not sort positions, so
existing ids are not renumbered.

### D3 — Title, tech tags and links

- Title: `myStandby - LandingPage` in both locales, exactly as written in AC-1
  and the repository name. It is a product/repository name, so it is not
  translated.
- Technologies: `["Vue.js", "GitHub CI/CD", "GitHub Pages"]`. These are the
  same strings, in the same order, as the michaelschreiber.net entry, which uses
  the same stack. Because `getTagColor` hashes the string, identical strings
  give identical badge colors on both cards. "TypeScript" and "Vite" are not
  added: the existing entry for the same stack does not list them either, and
  the story names only vue, github-pages and github-ci/cd.
- Links:
  1. `https://www.mystandby.app`, text key `projects.projectLinkTextWebsite`
     (new): "Visit website" / "Website besuchen".
  2. `https://github.com/mklschreiber/myStandby-LandingPage`, text key
     `projects.projectLinkTextGithub` (existing): "View on GitHub" /
     "Auf GitHub ansehen".

### D4 — Description (AC-2)

Use the following text verbatim:

- en: `A Vue application serving as the landing page for my app myStandby.`
- de: `Eine Vue-Applikation als Landing-Page für meine App myStandby.`

User-review revision (round 1, 2026-10-05): the user replaced the description.
The German text is the user's wording, verbatim. The English text is its
faithful translation. They replace the original AI-written texts (from the
repository description, the README, and the landing page hero):

- en (old): `The landing page for my Android app myStandby, which turns your phone into a smart nightstand display while it charges. A Vue 3 + TypeScript + Vite site that GitHub Actions builds and deploys to GitHub Pages on every push.`
- de (old): `Die Landingpage meiner Android-App myStandby, die das Smartphone während des Ladens in ein smartes Nachttisch-Display verwandelt. Eine Vue 3 + TypeScript + Vite-Website, die bei jedem Push per GitHub Actions gebaut und auf GitHub Pages veröffentlicht wird.`

Only the values of `projects.projectDescriptionMyStandbyLandingPage` in
`en.ts` and `de.ts` change. The key, `MessageSchema`, and `projects.json` stay
the same.

### D5 — Screenshots and responsive variants (AC-5)

Two images, in this order (desktop first, matching the michaelschreiber.net
entry):

| Base path | Source (Jira attachment) | Source size |
|---|---|---|
| `/mystandby_landing_macbook` | `page_macbook.jpg` | 1920×1280 (3:2) |
| `/mystandby_landing_phone` | `page_mobile.jpg` | 1920×1047 (~1.83:1) |

File names: `app/public/page_macbook*.jpg` already belongs to the
michaelschreiber.net entry, so the new files use the `mystandby_landing_`
prefix. `phone` (not `mobile`) matches the existing `page_phone` and
`mystandby_N_phone` names.

"Scaled for the different aspect ratios" is met the same way as for the
existing entries:

- Each source is scaled to the six widths in `IMAGE_WIDTHS` (320, 640, 960,
  1280, 1600, 1920). The aspect ratio of each source is kept. There is no
  cropping or upscaling (1920 is the source width, so that variant is only
  re-encoded).
- The browser picks the smallest sufficient variant through the existing
  `srcset`/`sizes`. The card's `aspect-ratio: 3 / 2` + `object-fit: cover`
  shows both formats in the same box. The phone image (~1.83:1) is cropped at
  the sides only on screen, exactly like the existing `mystandby_N_phone`
  images (also 1920×1047).
- JPEG quality 80 brings the 1920 variants from 0.9 MB / 1.6 MB down to
  about 350 KB, and the default 960 `src` to about 90 KB.

The unsuffixed original is committed next to the variants, as for every
existing image (source for later regeneration). It is never referenced by the
app.

Generation (macOS, run from the repository root):

```sh
S=/private/tmp/claude-501/-Users-schreiber-Projekte-michaelschreibernet/c54fd61b-0211-4a16-be4a-058d8c9a65a1/scratchpad
cd app/public
cp "$S/page_macbook.jpg" mystandby_landing_macbook.jpg
cp "$S/page_mobile.jpg"  mystandby_landing_phone.jpg
for name in mystandby_landing_macbook mystandby_landing_phone; do
  for w in 320 640 960 1280 1600 1920; do
    sips -s format jpeg -s formatOptions 80 --resampleWidth "$w" "$name.jpg" --out "$name-$w.jpg"
  done
done
```

Expected result: 14 files. A dry run of this exact command on the two sources
gave the following sizes (height px / file size). Check them with
`sips -g pixelWidth -g pixelHeight mystandby_landing_*`:

| Width | macbook | phone |
|---|---|---|
| 320 | 213 / 19 KB | 174 / 18 KB |
| 640 | 426 / 46 KB | 349 / 49 KB |
| 960 | 640 / 93 KB | 523 / 87 KB |
| 1280 | 853 / 137 KB | 698 / 143 KB |
| 1600 | 1066 / 192 KB | 872 / 198 KB |
| 1920 | 1280 / 346 KB | 1047 / 376 KB |

No code change to `IMAGE_WIDTHS`, `sizes`, or the carousel is needed.

### D6 — Out of scope

- The existing myStandby app description ("managing on-call duties") does not
  match the landing page's product text ("smart display while it charges").
  This story does not change it. A separate ticket can correct it.
- No changes to `seo.ts`, `sitemap.xml`, the route, or the overview page.

## Data Flow

```
projects.json ──(import, cast Project[])──> ProjectOverviewPage.vue
   [myStandby, myStandby - LandingPage, michaelschreiber.net]
        │ v-for (array order)
        ▼
   ProjectCard.vue
     ├─ t(titleKey), t(descriptionKey)               ← de.ts / en.ts
     ├─ images → srcset `${base}-${w}.jpg` (320..1920) ← app/public/
     │           lightbox `${base}-1920.jpg`
     ├─ technologies → .tech-badge (getTagColor)
     └─ links → v-for <a.project-link href=url>{{ t(textKey) }}
```

`ProjectCard.vue`: the template replaces the single `<a v-if="project.link">`
with the following. The existing external-link `<svg>` stays inside each anchor
unchanged:

```html
<div v-if="project.links?.length" class="project-links">
  <a
    v-for="link in project.links"
    :key="link.url"
    :href="link.url"
    target="_blank"
    rel="noopener noreferrer"
    class="project-link"
  >
    {{ t(link.textKey) }}
    <svg ...existing external-link icon...></svg>
  </a>
</div>
```

CSS: add

```css
.project-links {
  display: flex;
  flex-wrap: wrap;
```

`.project-link` rules stay. With `flex-wrap`, the two links sit side by side on
