| 2026-09-17 | Adopted the `improve-ci-cd-setup` concept: a new `.github/workflows/ci.yml`, separate from the existing deploy workflow, triggers on `pull_request` to `main` and runs three independent jobs (`lint`, `test`, `build`) so each is its own PR status check. The `lint` job runs a new, non-mutating `app/package.json` script (`lint:check`, i.e. `eslint .` without `--fix`) instead of the existing `--fix`-based `lint` script, because auto-fixing in CI would let a PR with real lint violations show green. The `test` job runs `npm run test:unit -- --run` to avoid relying on implicit `CI`-env watch-mode detection. |
