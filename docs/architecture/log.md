| 2026-09-23 | Adopted the `mobile-project-screenshot-carousel` concept for the Trello bug "Scaling but on mobile phones (project page)". Root cause: `.projects-grid`'s `1fr` track (`minmax(auto, 1fr)`) grows to `.project-card`'s min-content width. That width includes the gallery row's `n × 220px` image `min-width`s, because `overflow-x: auto` does not reduce intrinsic size, so the card (about 742px for three images) overflows every narrow viewport. Fixed with `min-width: 0` on `.project-card` and `minmax(0, 1fr)` on the grid. At the project's existing `max-width: 768px` breakpoint, the card shows one screenshot at a time. A `currentIndex` ref sets a `project-image--active` class, and CSS hides the other images, instead of a JS `matchMedia` template switch; this keeps desktop unchanged, removes hidden images from the tab order, and avoids loading them. Looping prev/next `<button>`s copy the `vue-easy-lightbox` arrow look (white chevron, 0.6 to 1 opacity, `rgba(0,0,0,.5)` backdrop, 4px edge offset) because the library does not export its arrow markup. They use two new flat `IconChevronLeft`/`IconChevronRight` components, localized `aria-label`s, and a polite live position status. The lightbox still opens at the visible image through the unchanged `v-for` index, and `sizes` gains a mobile `calc(100vw - 128px)` entry. |
